# Propsphere deployment

## Environment variables

- Local backend: copy `propsphere_backend/.env.example` to `propsphere_backend/.env` and fill in MongoDB Atlas and Cloudinary credentials.
- Local frontend: set `VITE_API_URL=http://localhost:4000` in `propsphere_frontend/.env`.
- Vercel: use `propsphere_frontend` as the project root, with `npm run build` and `dist` as the output directory. Set `VITE_API_URL` to the deployed Render API URL, without a trailing slash. Vite variables are included in the browser bundle; never put secrets in them.
- Render: create the service from `render.yaml` (or use `propsphere_backend` as the root directory). Fill `MONGODB_URI`, `FRONTEND_URL` (the deployed Vercel origin), and the three Cloudinary values in the Render environment. `JWT_SECRET` is generated by the blueprint.
- Redeploy the Vercel frontend after changing its environment variables.

## Project links

- Vercel dashboard: https://vercel.com/dashboard
- Render dashboard: https://dashboard.render.com/
- MongoDB Atlas: https://cloud.mongodb.com/
- Cloudinary console: https://console.cloudinary.com/

The frontend rewrite in `propsphere_frontend/vercel.json` keeps client-side routes working on refresh. The backend health endpoint is `/health`. Render's `PORT` value is used automatically.

New listing images are stored on Cloudinary. Existing records may still point to `/uploads/...`; keep those existing files in the backend repository for them to continue loading, or re-upload the images after deployment.
